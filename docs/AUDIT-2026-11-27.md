## 2. How each control type was validated

**Method.** `tests/controls-e2e.mjs` drives the real page in headless Chromium (Playwright) through *real input
events* — Playwright keyboard / mouse / wheel, CDP `Input.dispatchTouchEvent` for touch (multi-touch, cancel),
a mocked Gamepad — and asserts observable game state (`player.x`, `SN_TOUCH.pop`, `leverPct`, `S.scram`, DOM). The page
is served over HTTP from `game/small-nukem.html` with sibling assets from `android/app/src/main/assets/` (the shipped
layout). Headless has no GPU (~14 fps at DPR 1), so every wait is state-based. `node tests/controls-e2e.mjs
[--only=key,mouse,wheel,touch,pad,deck,ship25,layout]`; it skips with exit 0 if Playwright is missing. It is *not* part of
`value-checks.mjs` (which stays a fast pure-Node suite). Last full run on the final build: **86 passed, 0 failed** (`docs/audit-evidence/controls-e2e-run.log`).

Harness notes worth keeping (AGENTS.md §8 — a bot failure is not automatically a game defect): the Chief's panel
auto-collapses ~8 s after he speaks and moves the canvas under a finger, achievement cinematics swallow the next input by
design, and a mouse has no on-screen move zone (in AUTO mode the outer 35 % of the canvas steers) — the suite pins the layout,
silences cinematic offers and uses the right surfaces. Several apparent failures were exactly these; the real bugs they
sat beside are D1–D3, X1, F1, K1.

## 5. Physics changes and their gain

**One change, own commit: patch165** (block MD5 `a3385f4f…` → `be5a0982…`; the suite now pins the new hash).
Her `game()` sets `S.disp = 60` on the Level-3 grid emergency and never restores it until the next dispatch segment starts, 3–6 s after
the turbine returns; and, unlike every ordinary segment change (`grace = min(30, 4 + |step|/5)`), a forced turbine trip grants no
recovery time although the plant is at ~2 MWe and must re-ramp to the 150 MWe segment. Fix: at `ev.tu` 2→3 restore `S.disp` to the
segment target and grant the same grace formula.
**Gain** (competent operator, 3 seeds × 3 lever speeds): dispatch accuracy 0.850–0.857 → **0.909–0.956** (+0.06…+0.10),
score +2…+3, the displayed target is correct from the instant the turbine returns, and a forced trip no longer costs accuracy while
the plant physically recovers (grace 21.9 s for the 60 → 150 step). Her 33 constants, trips, kinetics untouched; all 538 original
checks unchanged. **This is a deliberate exception to Decision 9** and is flagged in `docs/MODEL-FIDELITY.md` and `AGENTS.md` §4.1 for Kevin
to confirm or revert (drop the patch165 effect; the other patches do not depend on it).
Game-layer changes that are *not* physics but touch pacing: patch176 (no auto-boost while a cinematic holds input).

  hold button (0.8 s, same language as SLC / feed pump) for mouse and touch; MANUAL vs AUTOMATIC overlay and an accurate Chief caption.

  1. **SHOW walkthrough** (171): SHOW starts the Chief's demo of the rest of the CURRENT level (takeover driver, from the current
     state), then the game advances on its own to the next level and demos it, through all three. Any keyboard / mouse / wheel / touch /
     gamepad input — or a second SHOW press — stops it at once (0.5 s start grace); steps it completes are DEMO-ASSISTED (+50);
     30 s cap, pacing and demo mechanics unchanged. Intermediate levels skip the score card; the final level scores normally.
     *Driver faults the walkthrough exposed* (174–179) were fixed so it can actually finish levels — see W1–W3.
  2. **Cinematics toggle** (172): `CINE: ON/OFF` right after AUDIO, same style, default ON, persisted as `sn.cine`; OFF drops every offer
     (no video, no audio), closes a running one.
  3. **Chief icon** (173): image only (no text, no label), ~30 % larger (24→31 px, phone 20→26 px), frame mirrors the follow state
     (green / red); remains a plain tap target — no press-and-hold.
     *Interpretation note:* in the shipped build the text SHOW button in the step bar is the follow control and the top-left icon
     toggles the guide bar; the brief says the icon "stays the SHOW/follow control it is today", so its existing tap behaviour is
     kept and its frame now shows the follow state rather than being rewired — Kevin may want the icon itself to press SHOW.
